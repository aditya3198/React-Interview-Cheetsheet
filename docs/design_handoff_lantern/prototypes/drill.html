Question

Why does setTimeout(fn, 0) run after a resolved Promise's .then?

Hint: think about which queue each callback lands in, and when the engine drains them.

Answer

Promise.then callbacks are queued as microtasks. setTimeout callbacks are queued as macrotasks. After every macrotask (including the script itself), the engine drains the entire microtask queue before running the next macrotask — so any resolved promise's .then runs first, even with a 0 ms timeout.

console.log('script');
setTimeout(() => console.log('macro'), 0);
Promise.resolve().then(() => console.log('micro'));

// ▸ "script"
// ▸ "micro"   ← drained from microtask queue first
// ▸ "macro"   ← next macrotask, after micro queue empty
