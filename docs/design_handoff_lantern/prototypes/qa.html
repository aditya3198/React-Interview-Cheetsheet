› 001 What's the difference between let, const and var? JSScope

var is function-scoped, let/const are block-scoped. const only freezes the binding, not the value.

var declarations hoist to the top of their function; they're visible throughout the function and can be redeclared. let and const hoist to the top of their block but stay in the temporal dead zone until evaluation, so reading them too early throws a ReferenceError.

const means the binding can't be reassigned — but the value it points at can still mutate.

const u = { n: 1 };
u.n = 2;     // ✓ mutating the object is fine
// u = {} ✗ TypeError: assignment to const
Asked at: Atlassian, Razorpay, Zerodha
› 002 What is hoisting? JSScope

Declarations move to the top of their scope at parse time; assignments stay put.

JavaScript reads through a function's body twice: once to register every var, function, let, const and class declaration, then again to actually execute. That first pass is "hoisting" — the declaration is made known before the line you wrote it on.

console.log(x);   // ▸ undefined  (var declared, not assigned)
var x = 1;
console.log(y);   // ▸ ReferenceError  (TDZ for let)
let y = 2;
Asked at: Flipkart, Swiggy, Microsoft
› 003 Difference between == and ===? JSTypes

== coerces, === doesn't. Use === unless you specifically want coercion.

== applies the abstract equality algorithm — it converts both sides toward a common type before comparing. === short-circuits to false the moment the types differ.

0  == false;   // ▸ true   (false → 0)
'' == false;   // ▸ true   ('' → 0, false → 0)
null == undefined; // ▸ true   (special case)
0  === false;  // ▸ false  (different types)
› 004 What's the box model? CSSLayout

Content → padding → border → margin. box-sizing changes whether width includes padding+border.

› 005 What's the difference between display: block, inline, inline-block? CSSLayout

block fills the line and respects all box properties; inline ignores width/height; inline-block sits inline but respects box.

› 042 Walk me through the event loop with async/await. JSAsync

Every await splits the function at that point and queues the rest as a microtask.

An async function returns a promise. The body runs synchronously up to the first await, then yields. The remaining code is registered as a .then on whatever was awaited — which means it ends up in the microtask queue, not the macrotask queue.

async function go() {
  console.log('a');
  await null;          // suspend; rest is a microtask
  console.log('b');
}
go();
console.log('c');
// ▸ "a"  ← sync up to the await
// ▸ "c"  ← caller continues
// ▸ "b"  ← microtask drains after sync code
Asked at: Stripe, Linear, Cred
