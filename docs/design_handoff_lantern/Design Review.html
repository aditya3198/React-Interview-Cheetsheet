A redesign of frontprep — now called Lantern

Less of a cheat‑sheet,
more of a study habit.

The site previously known as frontprep had the right surface area — JS, HTML, CSS, React. But it shipped only two of the six things an interview library needs: syntax cards and a flat Q&A list. Theory, version diffs, a playground, and a level-split Q&A were missing entirely, and drill mode was unusable for anyone who didn't already know all four languages. Renaming the product to Lantern let us start the visual identity over too — warm-dark, single amber accent, the light you keep on at night.

Findings02

Eight things, in priority order.

Each finding is paired with a concrete change. The first three are the ones I'd ship first — they reshape what the product actually is for the returning user.

Finding 01

Rename. “Frontprep” already exists — we are now Lantern.

High · brand

frontprep.pages.dev shares its name with at least one other live interview-prep service — the kind of overlap that quietly kills word-of-mouth and SEO long before it kills product. The new name had two jobs: be unambiguous in a Google search, and say what the site is without needing a tagline.

Lantern does both. The warm-dark UI with a single amber accent was already a lantern in everything but name — it is the light you keep on at night while you revise. The italic Instrument Serif "l" wordmark and the amber dot ship as a single adaptive SVG favicon that flips with the OS theme — no two assets, no <link> shuffling.

Finding 02

A visual identity that signals study, not a SaaS launch.

High · brand

The current palette uses pure magenta on deep purple, with white headlines set in the system font and a gradient running through the word "Frontend". This is the same toolkit a hundred AI startups landed on last year — it reads as generic launch page, not as a place to study.

frontprep is a personal tool, used at night, often half-asleep, often on a phone in a coffee queue. The aesthetic should sit somewhere between an O'Reilly book and a moleskine — quiet, ink-on-paper feel for the content, with a single warm accent doing all the highlighting. The four language colours stay, but only as small data points (dots, badges, progress fills) — never full-bleed backgrounds.

Drop
  • Magenta–purple gradient ground
  • Gradient text on display headlines
  • Glow shadows on buttons
  • System-font display type — no character
  • "✦ Frontend Interview Prep" sparkle badge
Adopt
  • Warm dark ground (#14110e) with cream type
  • Instrument Serif display · IBM Plex Sans body · JetBrains Mono code
  • One amber accent (#d4a04a) for state & highlights
  • Language colours used only as 6–10 px dots and fills
  • Editorial eyebrows / rules instead of badges
Finding 03

Ship the four missing sections.

High · scope

frontprep's nav promised six surfaces but shipped two. Theory was missing entirely. Version comparisons existed as long-form prose, never as a diff. Playground was a placeholder link. Q&A existed but as one flat list — a fresher and an architect saw the same 600+ questions in the same order.

Each of those four now has a prototype. Theory adopts a long-form-chapter layout with a drop-cap, inline diagrams, a reading-progress rail, and "drill this chapter" as a sibling action. Versions becomes a side-by-side diff between two selectable releases. Playground is a real-feeling code editor with tabs, live preview and a console. Q&A splits along two axes — depth (Core / Advanced) and audience level — covered in F6.

Finding 04

Drill must pick languages first — and show output in comments.

High · core feature

Two bugs made the existing drill mode unusable for most visitors. One: the deck shuffled all four stacks together with no way to opt out, so anyone who hadn't yet learned (say) React got hit with React questions and bounced. Two: every code snippet on the site showed input only — there was no annotation of what the code prints, which is exactly the trick interviewers test you on ("what does this log?"). A snippet without its output is a worse study aid than no snippet at all.

The redesigned drill opens on a setup screen: pick one or more languages from a four-card multi-select; pick a level (fresher / experienced / expert); pick a deck size; pick which sources fill the deck (Theory / Syntax / Core Q&A / Advanced Q&A / Version diffs / cards flagged "Review again"). A live summary line confirms what's about to load. Every code block now ends with one comment per output line, marked with a ▸ glyph so they stand out from inline comments. The same convention applies on syntax, theory, versions and Q&A pages — it's a system, not a one-off.

Finding 05

Make the hub remember the user.

Medium · IA & state

The hub today is a four-card chooser that's identical on first visit and hundredth visit. For an interview-prep tool, this is the most expensive miss on the page — the moment a user comes back, the site should already know what they were doing and which topics still scare them.

Three additions make the hub do real work: a per-language progress ring, "last seen" deep-link back into the exact card they left, and a "27 cards marked review again" shortcut. The card now also shows progress across all six sections (Theory / Syntax / Versions / Playground / Q&A / Drill), not just four. Progress lives in localStorage — no account required.

Finding 06

Q&A split into core/advanced × fresher/experienced/expert.

Medium · content

A 0–2 year fresher and a 5+ year staff engineer should not see the same Q&A list. The previous design did exactly that — every question, in source order, every visit. The new layout puts depth on one axis (Core: bedrock topics; Advanced: senior-only material) and audience on another (Fresher / Experienced / Expert). Inside each block, questions render in quick-read mode: every question visible at a glance, click to expand the answer, no drill loop required. "Drill these" CTA on each level block builds a focused deck from just that slice.

Finding 07

Theory is the spine. Give it long-form treatment.

Medium · content

Every other section on the site indexes against the theory chapters — syntax cards point at them, Q&A entries cite them, drill cards source their explanations from them. They deserve their own design language, not the same card-grid as syntax. Lantern's theory page borrows from book-editorial conventions: a drop-cap on the opening paragraph, Instrument Serif for headings and pull-quotes, an inline diagram per chapter, a reading-progress rail, and "drill this chapter / open in playground" as siblings of the text rather than buried in a footer.

Finding 08

Versions deserve a diff view, not a list.

Medium · content

"What changed in ES2024" or "what shipped in React 19" is the exact kind of recall an interviewer probes. Long-form prose is the wrong format — the interview answer wants a before/after diff: left column the old way, right column the new way, with a one-line "why it shipped" caption. The right-hand sidebar becomes a compare-versions control: pick ES2018 → ES2024 and see only the deltas, plus a visual timeline showing where each delta lands.

Finding 09

Search and filter, inside every content page.

Medium · navigation

JavaScript has 48 syntax cards and 110 Q&A. CSS has 88 Q&A. The current site has no search and no filter chip — to find "optional chaining" you scroll. This is the single biggest day-to-day friction.

Two things solve it: a page-level fuzzy filter pinned at the top (/ to focus, type to filter, supports operator strings like ?. or ??=) and a global command palette on ⌘K indexed across every card and question. While we're there, the existing right-panel "table of contents" earns its keep by becoming a real, sticky, current-section-highlighting TOC.

Finding 10

Treat emoji and brand colours as data, not decor.

Low · system

The previous sidebar used 📖 🕐 ⚡ 💬 as the only signifiers for Theory / Versions / Playground / Q&A. Emoji look juvenile next to the rest of the type, render differently on every OS, and break in screenshots and PDFs. The four language colours, meanwhile, were used as backgrounds — 4 px bars across cards and saturated text labels — which made the page noisy and overrode the role of "this is a state cue".

The system inverts both: section icons are now typographic glyphs in mono ({ } · § · v. · ▷ · ? · ↻), and the four brand colours move down to 6 px dots and 3 px progress fills, never bigger. Colour now means something specific.

Finding 11

A light / dark theme toggle, OS-driven by default.

Low · polish

The previous site was dark-only. People prep for interviews on the bus at 6 PM and at a desk at 9 AM — a forced theme is the wrong default. Lantern ships both: a warm-dark mode (the original lantern at night) and a paper-cream light mode (an open notebook at a coffee shop). The toggle lives in the top-right of every page; first visit picks up prefers-color-scheme, after that the user's explicit choice persists in localStorage. The favicon flips with the OS even when the in-app preference is overridden — it's a single SVG with media queries inside it.

Roadmap03

Three weeks, parallel-shippable.

Suggested sequencing. None of the rows depend on a re-architecture — the existing Next.js + SCSS modules setup absorbs all of this. Drill mode is the longest single piece and should start day one.

Week 01 · Rename & reskin

Earn the new name.

  • Rebrand. Lantern wordmark, adaptive favicon, all surface copy.
  • Swap tokens. Instrument Serif + IBM Plex Sans + JetBrains Mono.
  • Light + dark. Theme toggle, OS-driven default.
  • Strip emoji. Mono glyphs for sections.
Week 02 · Fill the gaps

Ship the four missing sections.

  • Theory. Long-form chapters with diagrams + reading rail.
  • Versions. From/to picker + diff cards.
  • Playground. Tabbed editor + live preview + console.
  • Q&A. Core/Advanced × fresher/experienced/expert.
Week 03 · Drill & memory

The primary action, finally working.

  • Drill setup screen. Language picker + level + sources.
  • Output in code comments. Site-wide convention.
  • Hub remembers you. Progress + last-seen + weak-cards drill.
  • ⌘K palette. Global fuzzy search.
